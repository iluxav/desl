# desl web forms: design

2026-11-21. Agreed with the author in conversation; this document writes it down for the plan.
Once built, `web-spec.md` and `SPEC.md` are rewritten from it in the same commits, and it stays
as the record of why.

## Intent

`desl web` was being built as a copy of the TUI in a browser: the sidebar, the agent's screen,
the waiting dialogs. The author's call: the browser should not repeat the terminal. It should
give the user and the agent richer ways to talk than a terminal prompt.

So the page becomes the place where an agent puts a **form** in front of the user: a few
widgets described in JSON (choices, a checklist, a document to edit, a diff to review, a look
to tune). The page draws it inside the thread's conversation, the user works in it and presses
Send, and the agent receives the result as data in its next prompt.

The five uses the author agreed to, each a widget the agent can push:

1. **Choosing:** options with their trade-offs, one click and a note, instead of typing "keep".
2. **Editing a document:** a section of a Markdown file of the project, edited in place and
   sent back, so the agent gets the exact edit, not "change the part about X".
3. **Tuning a look:** a live preview with sliders; the user drags until it looks right and the
   value goes back. One round instead of three.
4. **Approving a plan in parts:** steps as a checklist to untick, reorder and annotate.
5. **Reviewing a change:** each part of a diff accepted, rejected or commented on, before the
   agent commits.

Also wanted, at lower priority: a table to edit (task triage, research findings to tick), and
pictures to choose from (logo or colour variants).

## Goals

- An agent of each of the three kinds (Claude Code, Codex, Copilot) can push a form, and gets
  the user's answer as its next prompt.
- A form and its answer are part of the thread's record: in the conversation in order, after a
  restart, after a switch to another agent.
- The agent learns the form language from the tool itself. No skill and no prompt from desl is
  needed to use it.
- The page draws every widget from desl's own code. Nothing an agent writes runs in the page.

## Non-goals

- Copying the TUI: the agent's screen, its dialogs, subagents. Those stay in the terminal.
- Answering an agent's own approval dialogs on the page.
- A form that holds the agent's turn open until the user answers (the author's call: choice A).
- Agent-written HTML or JavaScript as a widget. The one exception is the preview widget, below.
- Accounts, sharing, remote access: unchanged from `web-spec.md`.

## Anti-goals

These would make it a failure even if it works:

- A form lost by a restart, a daemon restart or an install.
- An answer the agent can't tell from an ordinary prompt, or an agent left waiting for an
  answer that will never come without knowing it.
- A page that runs code an agent wrote, or reads a file outside the project because an agent
  named it.
- A tool description so long that every turn of every agent costs noticeably more.

## Approaches considered

| | Approach | Trade-off |
| --- | --- | --- |
| **A, chosen** | desl's own small widget set, sent as JSON, drawn by the page's own code | Covers the five uses exactly, including a real document editor and diff review. Nothing agent-written runs. A new widget kind needs a desl release |
| B | A2UI, Google's open JSON format for agent-made screens (1.0 announced November 2026) | A standard, portable to other apps. But general building blocks only: no document editor, diff review or live preview, so desl would add those as custom parts anyway; and its web renderers need a JavaScript build step or a vendored framework, which desl web has neither of |
| C | The agent writes HTML, shown in a sandboxed frame (the MCP Apps approach) | Anything is possible. But hundreds of lines per widget (slow, costly, every widget looks different), and agent code runs beside a page that can drive the agents |

The author chose A. C survives in one place: the preview widget shows HTML and CSS the agent
wrote, because there the HTML is the thing being tuned, not the widget. Scripts never run in it.

On delivery, also the author's call: **the tool returns at once** and the agent ends its turn;
the answer arrives later as its next prompt. The alternative, a tool call that waits for Send,
would hit each agent's tool time limit (Codex stops an MCP call after 60 seconds by default),
and a restart while it waits would lose the call. Returning at once needs no time limits,
survives restarts, and works the same in every agent.

On placement, the author's call: **forms show inside the thread's conversation**, at the point
the agent asked, rather than on a board per project. The user sees what the agent said just
before, and an answered form stays in the conversation as the record of what was chosen.

## How it works

### The tool

desl serves an MCP server over stdio, `desl mcp --thread <id> --socket <path>`. It speaks to
the daemon like any other client and can only act on its own thread. Two tools:

- `show_form {title, widgets[], send_label?}` returns at once:
  `Shown to the user as f-4b1e. End your turn now; their answer arrives as your next prompt.`
  An invalid form is refused with a sentence naming the widget and the field, so the agent can
  fix it in the same turn.
- `close_form {form_id}` withdraws a form the agent no longer needs. It closes as `withdrawn`.

**desl adds the server to each agent when it starts it**, through the agent's own launch flags,
so the user's agent configuration files are never edited and each server knows its thread
(the author was told this and did not object):

| Agent | Flag |
| --- | --- |
| Claude Code | `--mcp-config '<json>'`, plus `--allowedTools` for the two tools so the agent isn't asked |
| Codex | `-c mcp_servers.desl.command=…` and `-c mcp_servers.desl.args=[…]` |
| Copilot | `--additional-mcp-config '<json>'`, plus `--allow-tool` for the server |

The adapter boundary gains one input: `LaunchOpts.mcp`, the command and arguments of desl's
server, which each adapter turns into its own flags. `SPEC.md`'s adapter section changes with it.

**The agents' own question tools stay on** (the author's call, from the builder's question):
Claude Code's `AskUserQuestion` and Copilot's `ask_user` keep asking quick choices in the
agent's own screen, answered with the arrow keys in the same turn. Forms are for what the
terminal does badly. The tool's description says so: use a form when the user should edit,
review, reorder or compare something, or choose with room for a note; ask a quick question in
your own way. This settles `web-spec.md`'s open question 7: nothing is turned off.

**For scripts and agents without the tool**, the same through the CLI (the rule that the page
adds nothing the CLI lacks): `desl form new < form.json` (on behalf of `DESL_THREAD`),
`desl form list`, `desl form show f-4b1e`, `desl form answer f-4b1e --json '{…}'`,
`desl form close f-4b1e`.

### The form language

A form is a title, up to 30 widgets, and an optional label for its Send button. Each widget has
a `kind` and an `id`, unique in the form; the answer is an object keyed by those ids.

| Kind | The agent gives | The user does | The answer for its id |
| --- | --- | --- | --- |
| `markdown` | `text` | reads | (none) |
| `choice` | `options[] {label, detail?}`, `multi?`, `other?`, `value?` | picks one, or several | the label, or a list; `other` adds a typed answer |
| `checklist` | `items[] {id, label, detail?, checked?}`, `reorder?` | unticks, reorders, adds a note to an item | `[{id, checked, note?}]` in the user's order |
| `text` | `label`, `lines?`, `placeholder?`, `value?` | types | the text |
| `number` | `label`, `min`, `max`, `step?`, `unit?`, `value?` | slides or types | the number |
| `toggle` | `label`, `value?` | switches | true or false |
| `select` | `label`, `options[]`, `value?` | picks from a list | the option |
| `document` | `path` of a Markdown file of the project, `section?` (a heading) | edits the section in place, comments on a paragraph | `{saved, diff, comments[] {quote, note}}` |
| `diff` | `base?` (a git revision, default `HEAD`), `paths?` | accepts, rejects or comments on each hunk | `[{file, hunk, decision, comment?}]` |
| `preview` | `html`, `css`, `controls[] {var, kind: range or colour or select, …}` | moves the controls and watches the preview | `{var: value}` for every control |
| `table` | `columns[] {id, label?, edit?: text or select or check, options?}`, `rows[] {id, <column id>: value}` | edits the editable cells | the rows the user changed, with only the changed cells: `[{id, <column>: value}]` |
| `images` | `images[] {path, caption?}`, `multi?` | picks one, or several | the path, or a list |

Every widget may say `optional: true`; Send stays disabled until every other one is answered.

As built in milestone 5 (2026-11-22): the pictures list is `images[]`, not `items[]` as first
written, since the tool's flat schema already types `items` for checklists; a table's answer holds
only the changed cells; and `choice` and `images` take a `value` to start on, from the author's
note that what is true now should come pre-selected.

As built in milestone 3 (2026-11-22): the page answers a document with `{text, base?, comments}`
and desl turns it into `{saved, diff, more?, comments}` for the agent once it has saved; a refused
save is settled through `form_section`, the section as it is on disk now; files may end in `.md`
or `.markdown`, must have Unix line endings, and a section is at most 256 KB.

The tool's description carries this table in compact form. Its cost, counted in tokens, is a
budget: at most 1,500 tokens, since every turn of every agent pays it.

**Where data comes from.** An agent names files; it does not paste them. desl reads the
document, computes the diff with git in the thread's directory, and reads the images. So a form
stays small, and what the user sees is the file as it is, not the agent's copy of it.

**When it is read** (builder's question, settled as my call). The document's section and the
diff are read once, when the form is pushed, and kept with it: a diff is usually followed by a
commit that empties `git diff`, hunks must keep their numbers while the user reviews, and the
document's conflict check needs the text the card opened with. The copies, and the form's own
JSON, go into the store's content-addressed blobs (`$XDG_DATA_HOME/desl/blobs/`), and the
`form` event holds only their hashes, so events stay within `SPEC.md`'s 1 KB a event. Images
are read when a card is drawn, since twelve of them can be large; an answered card whose image
is gone shows its file name instead.

### What the user sees

```
┌ projects ─────────┐┌ web milestone · claude · working ─────┐┌ Waiting · 2 ───────┐
│ desl              ││ you: what next?                       ││ desl · next step   │
│   web milestone ◀ ││ claude: three ways to go…             ││ rebrand · logo     │
│   spec rewrite    ││ ┌ Which milestone next? ────────────┐ ││ ply · in its own   │
│ rebrand           ││ │ ( ) M4 questions                  │ ││   screen: answer   │
│   logo            ││ │ ( ) M5 live document              │ ││   in the terminal  │
│                   ││ │ Note: ___________          [Send] │ ││                    │
│                   ││ └───────────────────────────────────┘ ││                    │
│                   │├───────────────────────────────────────┤│                    │
│                   ││ prompt to web milestone…       [Send] ││                    │
└───────────────────┘└───────────────────────────────────────┘└────────────────────┘
```

- **Left:** projects, each with its agent threads, one line each: the status mark, the title,
  the age. No subagents, no shells or file managers.
- **Middle:** the selected thread's conversation, as the Conversation tab draws it today, with
  each form as a card at the point it was pushed. An open card is live; an answered one stays,
  read-only, showing the answer and when it was sent. The prompt box stays below, and Stop
  stays in the header while the agent works. There are no tabs any more.
- **Open wide:** a document, diff or preview card has a button that gives it the middle and
  right columns, and a way back.
- **Right, "Waiting":** every open form in every project, oldest first; a click selects its
  thread and scrolls to the card. A thread waiting on a dialog in its own screen gets one line
  saying so, since it is answered in the terminal.
- **Send** answers the form. **Dismiss** closes it unanswered, and the card says it was
  dismissed. The agent is told in a line before its next prompt (my call, from the builder's
  question: the tool told it an answer would come), as a brief is put before one today:
  `desl: the user dismissed f-4b1e "Which milestone next?" without answering.` Dismissing starts
  no turn by itself.
- **Work not sent yet is kept** (my call, from the builder's question): a document edited for an
  hour, a diff half reviewed. The page sends the card's state to the daemon a second after the
  last change (`form_draft {form_id, draft}`); the daemon keeps it beside the open form, not in
  the log, and drops it when the form closes. A reload, an install, a daemon restart or another
  tab opens the card as it was left; two tabs editing one card at once keep the later save.

### Lifecycle and record

1. `show_form` → the daemon checks the form, gives it an id `f-xxxx`, and appends a `form`
   event to the thread's log: `{form_id, title, widgets, send_label?}`.
2. The thread has an open form. Once the agent's turn is over, the thread is `waiting`, with the
   same marks as an agent's own dialog: amber in the TUI's sidebar and the page, the bell, the
   title count. While the agent is still working, it stays `working`.
3. Send → the page sends `form_answer {form_id, answer}`. The daemon checks the answer against
   the form, appends a `form_answer` event `{form_id, answer, by: "user"}`, and sends the agent
   this prompt through the existing `prompt` path (queued while it works, held while its screen
   asks something):

   ````
   desl: answer to f-4b1e "Which milestone next?"
   ```json
   {"next": "M5 live document", "note": "start with comments"}
   ```
   ````

4. `close_form` appends `form_answer` with `by: "withdrawn"`, Dismiss with `by: "dismissed"`;
   neither sends a prompt of its own.

Open forms are worked out from the log, so a restart of anything keeps them. A switch to another
agent keeps them open, the answer goes to whichever agent the thread runs then, and the copied
conversation includes each form and its answer as text. A fork does not copy open forms.

A prompt the user types to the agent does not close an open form: a document may take an hour,
and the user may talk to the agent meanwhile.

**Protocol.** New commands within major version 1: `form_new {thread_id, form}` replies
`form {form_id}`; `form_answer {form_id, answer}`, `form_close {form_id, by}` and
`form_draft {form_id, draft}` reply `done`; `form_get {form_id}` replies the form, its copies,
its draft and, once closed, its answer.
The `thread` event carries the thread's open form ids. The bridge's `view` message gains the
open forms list for the right column, and its `conversation` items gain a `form` kind carrying
the form, its answer if any, and how it closed.

**The TUI** shows a thread with an open form as waiting. Its history view (`prefix [`) shows
the form and the answer as text, with "answer it in the browser: prefix v". `prefix v` on such a
thread opens the page on that thread.

### Documents, diffs, images

- **Document:** the path must resolve, links followed, inside the thread's directory (its
  worktree, for a worktree thread), end in `.md`, and be under 1 MB. The card shows the section
  (the whole file without one) for editing, with a comment on any paragraph. Send saves the
  section into the file in one write, but only if the section on disk is still what the card
  opened with; if it changed meanwhile, the card shows both versions and saves nothing until the
  user picks. The answer carries the unified diff of the user's change and the comments.
- **Diff:** `git diff <base> -- <paths>` in the thread's directory, split into hunks, at most
  2,000 lines; beyond that the card says how much it left out. desl applies nothing: the agent
  acts on the decisions.
- **Images:** files inside the thread's directory, PNG, JPEG, GIF, WebP or SVG, up to 10 MB each
  and 12 per form. The bridge sends them to the page as `data:` URLs over the socket, so no new
  HTTP route needs the key.
- **Preview:** the agent's HTML and CSS go into an `<iframe sandbox srcdoc>`: no scripts, no forms,
  no navigation. The page's CSP still applies inside it, so nothing loads from outside. The
  controls are drawn by the page and set CSS variables on the frame's root. As built (milestone 5),
  the sandbox is `allow-same-origin` and nothing else, not an origin of its own: the CSP refuses
  inline style, so the page fills the frame itself through the DOM and a constructed stylesheet,
  which needs its document. That leaves no script anywhere to use the shared origin, and a test
  (`a_preview_frame_never_runs_script`) fails if any page file ever allows one.

## What goes away

All of it is unreleased, so no protocol version changes:

- The Screen tab, the vendored xterm.js and its fit addon, and the page's input and resize.
- In the daemon, the size rule for pages (`Asked.web`, `pty_size`, the size in `attached`), and
  the answers to terminal queries it gives when only a page shows a thread.
- Milestone 3's dialog text: `thread.asking` and the cards that showed it.
- In `web-spec.md`: questions and `desl ask` (a form with one `choice` replaces them), the
  agent's screen on the page, and the waiting list of approvals. The live document and the task
  list on the page move to "Later": the `document` widget covers editing a document with an
  agent, and the task list stays in the TUI.

## Budgets

| Moment | Budget |
| --- | --- |
| `show_form` called to the card on an open page | < 300 ms |
| Send to the prompt typed into an idle agent | < 1 s |
| The tool's description, counted in tokens | ≤ 1,500 |
| A form, as JSON | ≤ 256 KB |

## Milestones

1. **The page reshaped** (about 2 hours): the screen, xterm.js and the page size rule removed;
   the left column as projects and threads; the conversation as the middle; the right column
   ready for forms.
2. **Forms** (about a day): `desl mcp`, the launch flags for all three agents, the events, the
   protocol, `desl form`, and the widgets `markdown`, `choice`, `checklist`, `text`, `number`,
   `toggle`, `select` in the conversation and the right column. Done when Claude Code, Codex and
   Copilot each push a form in a test project and get the answer as their next prompt, and a
   form survives a daemon restart.
3. **Document** (about half a day): editing, comments, the conflict on save.
4. **Diff review** (about half a day).
5. **Preview, table, images** (about half a day).
6. **Security review** (dropped by the author on 2026-11-22; each milestone's review covers it): someone who didn't write it tries to run script from a form, read a file
   outside the project through a document, image or diff, and drive an agent from another site.
