# desl web alone: the agent's screen and the thread's actions on the page

2026-11-24. The author's call in conversation: "go, all three".

## Intent

The author likes desl web, most of all the live conversation and the forms, and wants to use the
page alone, without the TUI open beside it. That needs three things the page lacks: the agent's
own screen, to type into it and answer its dialogs; the actions on threads that only the TUI has
today; and pasting a screenshot into an agent.

This turns around the call of 2026-11-21 that "the agent's screen stays in the terminal"
(`web-spec.md`, "Redirected"). The screen was on the page then for a day (4798f4a) and worked:
keys, pastes and the mouse reached the agent. It comes back from the history, not from scratch.

## Goals

1. **The screen (milestone 1).** A third view of a thread, **Conversation | Highlights | Screen**:
   the agent's own interface drawn by xterm.js, with the keys, pastes and the mouse going to it.
   Its dialogs are answered there, so the waiting column's line for a thread that asks in its
   screen opens that screen instead of sending the user to the terminal.
2. **The thread's actions (milestone 2).** What the TUI does to threads, on the page: a new
   thread in a project (an agent, the shell, the file manager), a directory opened as a project,
   and on the thread on screen switch, restart, fork, rename and close. Shells and file managers
   are listed in the left column and open on their screen. The prefix key works on the page as in
   the TUI for these actions and for moving between threads.
3. **A screenshot pasted (milestone 3).** Pasting an image into the screen gives the agent the
   image, as `ctrl+v` does in a terminal.

## Non-goals

- The TUI changes nothing. It stays the full client; the page becomes a second full one.
- Splits, zoom, detach, the sidebar's key mode and the info box (`prefix %`, `z`, `d`, `w`, `i`).
- Remote access. The page still answers only at 127.0.0.1 and localhost.
- Keys the browser keeps: `ctrl+w`, `ctrl+t`, `ctrl+n` and `ctrl+tab` act on the browser in a
  tab. The page says so where the screen is; it cannot take them.

## Approaches

| | Approach | Trade-off |
| --- | --- | --- |
| **A, chosen** | Bring back 4798f4a's screen (xterm.js 6.0.0, the daemon's size rule) as a third view; add the actions as buttons and menus that send the daemon's existing commands; the prefix key read by the page before xterm.js sees it | Known to work; one size rule for a thread on two screens; no new daemon commands for the actions. The binary grows about 1.9 MB again |
| B | A terminal of the page's own (canvas, no xterm.js) | Smaller binary; months of emulator work desl already did once in Rust |
| C | Run the TUI itself in the page (a terminal of the TUI) | Every feature at once; the page's conversation, forms and tasks would be beside a second sidebar and key line, and the browser's own keys would still be lost |

## How (the builder's calls)

- **One thread on two screens.** The daemon tells a page from a TUI by `hello`'s name again.
  While a TUI shows a thread, the TUI's size wins (it draws the agent through an emulator of its
  pane); the pages hear `pty_size` and draw at it. Once no TUI shows it, the page that asked last
  sets the size. The daemon answers the agent's terminal questions whenever no TUI shows the
  thread; the page drops the answers xterm.js would give. As 4798f4a had it.
- **The prompt box** shows under Conversation and Highlights, not under Screen, where the agent's
  own input has the keys; at phone width it shows under all three.
- **Copying** from the screen: a selection (shift+drag where the agent takes the mouse) is copied
  with `ctrl+c` or `ctrl+shift+c`; without a selection `ctrl+c` goes to the agent.
- **Actions** send what the TUI sends: `new_thread`, `switch`, `restart`, `fork`, `rename`,
  `remove_thread`. Close asks again in place, as the TUI's `y` does. The agent menus list the
  agents installed and logged in, the current one marked.
- **Opening a directory**: the page asks desl web for the same list `prefix o` shows (projects,
  zoxide's directories, git repositories under home, folders beside them), filtered as typed; a
  typed path is opened as it is. The pick goes on to the new-thread menu for that directory.
- **The prefix** is the one in `config.toml` (`general.prefix`), which desl web tells the page.
  After it: `c` new thread, `o` open a directory, `s` switch, `r` restart, `f` fork, `,` rename,
  `x` close, `n`/`p` next and previous thread, `1`…`9`, `l` the thread before, `[` the
  conversation, `prefix` again sends the prefix to the agent. `alt+j`/`alt+k` move between
  threads, as in the TUI.
- **Paste (corrected after use).** `ctrl+v` (`cmd+v` on macOS) belongs to the browser, which
  delivers a paste event with the clipboard's contents. Text follows xterm.js's normal paste
  handling, bracketed when requested. A picture with no text sends `0x16` to the agent,
  which reads the image from the local clipboard; a shell gets nothing. `ctrl+shift+v` is
  the browser's plain-text paste. Sending `0x16` directly on Ctrl+V was the initial design;
  it made copied text fail with the agent's "no image on clipboard" error.
